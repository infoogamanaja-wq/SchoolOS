# Platform interface and workflow audit — 5.1.0

The audit covered the installed script's login/static entry pages, role dashboard/router, account provisioning, subscription helpers, workspace activation, menu destinations, demo generation/session handling, credential storage and existing portal regressions. It did not inspect a production cPanel installation or certify every external service/roadmap item as live.

## Menu and feature boundaries

The simplified school-owner menu now routes to working overview/setup, Students, Parents, Teachers, Admissions, Portal Accounts, Account Links, Academics, Attendance, Results, Learning, Finance, Community Hub, School Services, School Operations, School Intelligence, School Setup, Support and Audit. Twenty navigation links are checked in the new HTTP suite. Other roles retain their authorized workspaces, with new role-specific starting actions. A missing account link is a setup state, not permission to show another person's data.

The workspace health screen checks complete readiness functions for Family/Learning/Operations/Services/Intelligence and sentinel availability for the core student, Finance and school-setup schemas. It is an installation check, not a full consistency scan or a promise that provider credentials, every field, licence or historical record is correct. Core feature workflows are covered by the retained domain/HTTP/concurrency suites; a successful route alone is not their only evidence.

Existing marketplace/experimental/duplicate generic controls are not promoted into the simplified school-owner menu as fully implemented school services. School-store procurement and actual approved integrations remain in their tested workspaces. Existing SaaS catalogue configuration such as coupons/add-ons/limits/feature records is not falsely presented as a new automatic discount, metering or entitlement engine. The new signup uses only its documented plans, cycles and trials. Do not sell unconfigured integrations or unsupported automation as included live capabilities.

Live gateway settlement, SMTP/delivery, WhatsApp templates/consent/credits, OneSignal, scheduled workers, domain DNS/TLS, physical GPS/handover, regulated financial arrangements and privacy/legal assessments remain deployment requirements. The demo intentionally blocks live provider activity and uploads; it does not fake success. Native browser tests emulate narrow screens, not a physical Android or assistive-technology certification.

File rollback preserves records and verified dependency bytes; it does not reverse business transactions or prove hosting-related deletions can never recur. Production server logs were unavailable.
